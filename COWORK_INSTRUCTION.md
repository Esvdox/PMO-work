## Когда запускать апдейт

Запускай каждый раз, когда **меняешь данные в `PMO_Portfolio_Master_v7.xlsx`**:

- скорректировал % выполнения, EV/AC/PV у проекта
- добавил или закрыл риск
- сдвинул baseline или forecast
- сменил статус проекта (Активный ↔ Приостановлен ↔ Backlog)
- добавил новый проект (новая строка в `01_Проекты`)

Если ничего не менял в xlsx — апдейт не нужен.

## Шаг 1. Подготовь xlsx

1. Открой `PMO_Portfolio_Master_v7.xlsx`
2. Внеси изменения в нужные листы
3. **Ctrl+S** → закрой Excel

Excel при сохранении пересчитает все формулы (% выполнения, SPI, CPI, Откл. дн., Статус RAG, Score, EMV). Это критично — без открытия Excel формулы остаются «зависшими» и Cowork прочитает NaN.

⚠ Если забыл открыть xlsx после правок → Cowork сообщит «в xlsx NaN в вычисляемых колонках» — открой и пересохрани.

## Что Cowork делает (13 шагов из промпта)

1. Создаёт backup: `backups\index-YYYY-MM-DD-HHMM.html`
2. Читает все 5 листов xlsx через pandas
3. Пересчитывает агрегаты портфеля (total/active/suspended/backlog, бюджет, средний %, RAG-распределение)
4. Считает EVM-блок (SPI, CPI, EAC, CV, BAC)
5. Собирает `DATA.managers` — по каждому PM его активные и приостановленные проекты
6. Собирает `DATA.backlog` — 9 P4-проектов
7. Строит `DATA.risksMatrices` — 5×5 матрицы по каждому активному проекту
8. Топ-5 рисков по score (P×I)
9. Timeline — ближайшие 10 запусков
10. Обновляет `DATA.meta.updatedAt`
11. Аккуратно заменяет блок `const DATA = window.DATA = { ... };` в `index.html` — НЕ трогая HTML/CSS/JS/фото/инициативы
12. Делает `git commit` и `git push origin main`
13. Выводит финальный отчёт: что изменилось vs вчера, URL опубликованной версии

## Если Cowork сломался — частые случаи

### «git операции не работают / unable to unlink .git/index.lock»

Известный баг Cowork на Windows (issue #55206) с git внутри sandbox-bash на mounted-папке. Cowork сообщит:

> ⚠ git операции упали — нужен ручной push в PowerShell

Открой PowerShell и сделай вручную:

```powershell
cd C:\Users\sivanov\Desktop\Repo-for-claude-ppm-status
Remove-Item .git\index.lock -ErrorAction SilentlyContinue
git add index.html
git commit -m "Daily update $(Get-Date -Format 'yyyy-MM-dd HH:mm')"
git push origin main
```

Это занимает 30 секунд. Cowork своё дело сделал (обновил `index.html`), просто доводит push до конца ты сам.

### «xlsx не читается / в данных NaN»

Cowork сообщит: «формулы в xlsx не пересчитаны». Закрой xlsx → открой заново → **Ctrl+S** → закрой → запусти Cowork снова.

### «xlsx заблокирован другим процессом»

Закрой Excel (он держит файл). Если Excel не открыт — открой Диспетчер задач (Ctrl+Shift+Esc), найди процесс `EXCEL.EXE`, заверши его.

### «Cowork сломал index.html»

Не страшно — есть backup. Восстанови из `backups/`:

```powershell
cd C:\Users\sivanov\Desktop\Repo-for-claude-ppm-status\backups
dir   # увидишь все backupы по дате
copy index-YYYY-MM-DD-HHMM.html ..\index.html
cd ..
git add index.html
git commit -m "Rollback to backup"
git push origin main
```

## Что НЕ нужно делать через Cowork

Cowork работает **только с данными** (блок `DATA` в HTML). Если ты хочешь:

- **изменить вёрстку дашборда** (добавить ветку, новый блок, поменять цвета, переделать секцию проекта)
- **добавить новые иконки, KPI, графики**
- **исправить баг в JS-рендере**
- **добавить новую секцию документа** (например, плановый WBS-вид)
- **обновить методологию** (тексты hero, инициативы, бэклог)

— **напиши мне в чат Claude** (Anthropic.com, не Cowork). Я переделаю HTML/CSS/JS, протестирую, дам тебе обновлённый файл, ты заменишь `index.html` и запушишь.

Граница простая:
- **Цифры/факты меняются** → Cowork
- **Структура/код меняется** → я

⚠ **Примечание про `PROJECTS_DETAIL`:** этот блок содержит детальные данные проектов (паспорта, риски, описания). Сейчас он обновляется только когда я даю тебе новую версию `index.html`. В будущем можно научить Cowork обновлять и его — напомни если потребуется.
